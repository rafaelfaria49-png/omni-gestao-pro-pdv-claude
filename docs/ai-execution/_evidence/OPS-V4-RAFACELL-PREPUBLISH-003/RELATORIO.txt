NOVO BLOQUEADOR P1 — RESERVA APAGÁVEL NO PATCH GENÉRICO
Entrada pública existente: app/actions/operacoes.ts, updateOSPayload.
Boundary: lib/operacoes-v3/os-payload-lock.ts, semCamposFinanceirosDoServidorV3.
O boundary só protege os campos de envio quando orcamento é um objeto truthy.
Com orcamento=null, a proteção não é executada; mergePayload aplica o null.
Assim, o registro de api_em_andamento e a evidência podem desaparecer.

Reprodução no PostgreSQL descartável, com Prisma e Server Actions reais:
1. Preparar e iniciar API; o transporte mockado lança resultado de rede incerto.
2. Confirmar reserva api_em_andamento e orçamento em rascunho no banco.
3. Chamar updateOSPayload com orcamento=null. A chamada é aceita.
4. Repor uma proposta válida por patch, preparar e chamar API novamente.
5. O transporte mockado é chamado duas vezes; a primeira reserva foi perdida.

Teste de aceite: test/ops-v4-rafacell-prepublish-003/concorrencia.pg.ts.
