Configuração do CI

.github/workflows/ops-v4-rafacell-contracts.yml usa pull_request para main,
inclusive Draft, com paths dos contratos e dependências pertinentes. Actions
fixadas por SHAs conferidos contra os repositórios oficiais; contents: read,
persist-credentials: false, nenhum secrets.*, environment produtivo, deployment,
pull_request_target, banco externo ou WhatsApp real. Node 24, PostgreSQL 17 efêmero.
URLs idênticas, usuário/nome exclusivos, loopback, banco vazio antes do DDL,
env sintético e ausência de .env são exigidos. Processos não herdam credenciais
do perfil local. HTTP externo é bloqueado e o transporte dos testes é mockado.
Somente no build, GET HTTPS sem Authorization/Cookie aos endpoints públicos
fonts.googleapis.com/css[2] e fonts.gstatic.com/s/ é permitido: o primeiro CI
mostrou que o next/font existente depende desses downloads. Não há liberação
de rede para WhatsApp, aplicação remota, credenciais ou banco externo.
Build exige MIGRATION_SKIPPED, rejeita MIGRATION_RUN/SUCCEEDED, e TypeScript é
checado separadamente porque o Next ignora erros de tipo na configuração atual.
Temporários ficam fora dos artifacts; relatórios/logs sanitizados são retidos 14 dias.

As 16 falhas históricas NÃO são skip, xfail, continue-on-error ou allow-failure.
O check de regressão fica realmente vermelho enquanto o HEAD as apresentar.

este documento não antecipa um CI verde. O primeiro run 39535972441 confirmou
347 focados, 23 UI, 39 PG, TypeScript/lint aprovados e as mesmas 16 históricas,
zero novas. O build desse run falhou pelo bloqueio das fontes públicas; a
